description: Create a Architecture Decision Record (ADR) to scope out an architectural decision, align the model and user vision of the technical trade-offs, consequences, and context that precipitated the need for this decision, and to clarify how the decision will be enacted.
disable-model-invocation: true
---

Use the following template to guide the creation of the ADR. Once it is complete, and both the user (them) and the model (you) are:

1. satisfied that the decision is defined well enough, and
2. share the same understanding of the architectural decision being made

write the document to the project's `docs/adr/` directory.

```md
# Decision Title ADR

This is an Architecture Decision Record for `Decision Title`.

## Status

Proposed, Accepted, Deprecated, or Superseded (and by what).

## Context

What situation or constraint led to this decision?

## Decision

What did we decide to do, and what alternatives did we consider and reject?

## Consequences

What tradeoffs, risks, or follow-up work result from this decision?
```

Call the Skill tool with `grilling`.
